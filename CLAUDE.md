## Project Overview

Raycast extension that lists the profiles from iTerm2's preferences and opens the selected one in
a new tab or window. macOS only: it reads iTerm2's binary plist and drives the app with AppleScript.

## Build

Use the Makefile for everything.

```
make install     # check-node + install dependencies (node_modules is gitignored)
make build       # ray build -e dist: compile and type-check
make dev         # ray develop, installs the extension into Raycast for testing
make lint        # ray lint (ESLint + Prettier + manifest and icon validation)
make fix-lint    # ray lint --fix
make publish     # ray publish, submits to the Raycast store
```

This Makefile does **not** source nvm. Its `check-node` prerequisite requires the active Node major
to *exactly* match `.nvmrc` (24) and fails with `Node 24 required, found vX. Run: nvm use`
otherwise. Run `nvm use` yourself first.

Every target goes through `install`, and `node_modules` is a file target depending on
`package.json` and `package-lock.json`, so dependency changes are picked up automatically.
There is no `clean` target; remove `node_modules` by hand for a fresh install.

`make build` only compiles. Run `make dev` to get changes into the Raycast app.

## Architecture

- **`src/iTermProfiles.ts`** - all the platform work.
  - `getItermProfiles()` parses `~/Library/Preferences/com.googlecode.iterm2.plist` with
    `bplist-parser` and returns the named entries of `New Bookmarks`.
  - `openProfile(name)` runs `appleScriptToOpenProfile(name)` through `runAppleScript` from
    `@raycast/utils`. The script reuses the front window when one is open (new tab) and creates a
    window otherwise.
- **`src/index.tsx`** - renders the profiles as a `<List>` via `useCachedPromise`. Errors from
  either step surface as a failure toast.

## Notes

- **No test suite.** `make build` (type check) and `make lint` are the only verification.
- `bplist-parser` v0.5 dropped its default export: import `{ parseFile }`, which resolves to a
  single-element tuple, so destructure it (`const [prefs] = await parseFile(...)`).
- AppleScript goes through `@raycast/utils`, not the `run-applescript` package, which is ESM-only
  and redundant here.
- `@raycast/api` v2 supplies `@types/node` and `@types/react`; do not add them to
  `devDependencies`. TypeScript 6 no longer auto-includes `@types`, so `tsconfig.json` lists them
  in `compilerOptions.types`.
- TypeScript is held at 6.x: `@raycast/eslint-config` requires `typescript <6.1.0`.
- `raycast-env.d.ts` is generated by `ray build` and gitignored. Do not edit.
